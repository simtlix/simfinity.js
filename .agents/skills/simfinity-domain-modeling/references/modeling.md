# Modeling decisions

| Choice | Contract |
| --- | --- |
| Entity | `id: GraphQLID`, `connect(null, Type, singular, plural, controller, onModelCreated, stateMachine)`; MongoDB may supply a model, PostgreSQL requires null |
| Embedded value | `extensions.relation.embedded: true`, supporting type via `addNoEndpointType`; object updates merge, supplied arrays replace |
| Independent reference | Object field with `relation.connectionField`; input `{ id }`, stored ObjectId/UUID |
| Referenced children | List field with `connectionField` identifying the child's stored parent link; input `{ added, updated, deleted }` |
| Server-managed field | `readOnly: true`, populated by trusted hooks; still readable unless separately protected |
| Computed read on a record | Since 3.8.0: `extensions.virtual: true` with the field's own `resolve`; never stored, written, filtered or sorted, read after the type's scope. At 3.7.0 a `readOnly` field with its own resolver is still stored |
| Sensitive output | Permission rule or omit from the public type; `queryable: false` independently forbids filter/sort/group paths |
| Invariant | GraphQL shape plus `extensions.validations`, controller for persisted/context-dependent checks; unique database constraint for concurrency |

For an order with lines, `Order.lines` and `Line.order` can both use `connectionField: 'orderId'`. This retains an existing storage field while presenting a typed relationship. Use field thunks for circular references; recursive embedded types are not a substitute for entity references. A many-to-many relationship generally needs an explicit association entity.

Use typed fields or an embedded object for one set of settings that changes under the same owner, access policy and revision. Give a setting its own record when its identity, revision, sharing or lifecycle requires it. Editable lists of dependent records fit referenced children when items need stable identity or individual edits. An embedded list fits value items replaced together. If two independent records are linked and the link carries role, effective dates or permissions, model an association with two references and validate both endpoints. A JSON string containing ordinary business lines prevents generated validation, references and query paths. An encrypted payload, rich-text document or external opaque object may legitimately remain opaque; model exposed facts separately without weakening its privacy requirements.

Register once at startup, then build the schema. Create fresh type objects per runtime when generated relation resolvers bind them. Await PostgreSQL initialization before serving operations. The `createSchema()` include lists select entity types for generated roots. For an included mutation type, apply exact operation permissions to the generated CRUD and state actions. If parent hooks maintain totals, exclude the child type from standalone mutations or maintain the invariant from those paths too. Serve the original schema and install resolver authorization in place.

## Inspect rather than infer

Create inputs omit entity IDs and read-only fields; update inputs require the ID and have different requiredness. Referenced `added` items cannot choose IDs. Keep external identifiers and idempotency keys in separate fields. Prefer a variable of the generated input type for the whole mutation payload. If you bind reference IDs individually, check the nested scalar type. In 3.19.0 the generated reference input uses `String!` for `id`, even when the root ID is `ID`. Omission preserves a value; explicit null clears a nullable value under the documented update contract. A field originally declared non-null can ignore an update null rather than clear it; inspect the actual schema and test stored state before promising a UI clear action. Do not force Mongo `_id` or stored nulls through adapter overrides.

`GraphQLNonNull` and validation are different. Built-in validation helpers return CREATE/UPDATE arrays; merge those arrays when combining helpers. A shallow spread can replace earlier validation. Reuse validated scalar instances with their documented storage mapping; creating a same-named scalar does not reproduce its identity or normalization contract. On partial update, `modelArgs` is not the whole record: session-bound checks must account for stored values and `$unset`.

GraphQL Int is signed 32-bit; design monetary/count fields for actual bounds. For portable enum ordering and states, prefer string internal values matching names. Do not assume MongoDB reference checks equal PostgreSQL foreign keys; Mongo transactional integrity is opt-in and native writes fall outside it.

## Static checks and storage changes

The optional `@simtlix/eslint-plugin-simfinity` 0.5.0 adds bounded model-field, relation/storage and schema checks to `recommended-3.8`; `advice-3.8` is separately opt-in. Preserve the app's lint configuration and package manager. The plugin is an independent development dependency, not one of the aligned runtime packages. These presets explicitly target 3.8.0, do not detect the installed runtime, and do not certify later features or authorization/transaction behavior. Unknown provenance or analysis limits can suppress diagnostics; a clean lint result is not proof of a correct model. See [application linting](https://simtlix.github.io/simfinity.js/guide/linting.html).

`connectionField` is a single storage field name, not a dotted path. Verify the child's actual parent link for editable collections, scalar/storage compatibility and registered targets against the chosen engine. For a new single reference, reuse the legacy storage key if its stored type is compatible. Give that key one stored field declaration. For example, `parent: Parent` with `connectionField: 'parentId'` already owns `parentId`. Preserve an old scalar API field through a compatibility DTO. If only the inverse collection is needed, PostgreSQL can infer its foreign key from a child’s scalar `GraphQLID` field. A legacy string ID may need conversion to the engine’s reference representation. Verify old records with null, missing or dangling IDs, and define the behavior for archived targets and deletion. Moving a stored link or removing its stored field requires a data/schema migration. PostgreSQL initialization does not automatically alter existing tables. Validate a proposed migration against a disposable copy of the relevant data shape.
