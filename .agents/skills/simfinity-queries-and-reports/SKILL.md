# Query and report with explicit semantics

Check the installed version, selected engine, actual type relationships and access policy. This guidance targets 3.7.0. Define the metric, visible population, ordering, pagination and freshness requirements before choosing an implementation.

Use the [report guide](references/reports.md) to distinguish response selection, stored-field aggregation, pure domain calculation and materialized read models. Apply visibility before counts, grouping and paging. Fields selected in GraphQL are not automatic database projection pushdown or authorization.

Reuse generated filters/scopes/aggregates where they express the requirement; from 3.12.0, a frequent list read with a fixed predicate and typed params is a named view (`registerView`). For unsupported calculations or traversal, use an explicitly authorized application report or read model, or, after 3.7.0, a virtual field (`extensions.virtual`) on the type the read describes; keep native engine details in infrastructure. Do not rewrite Simfinity's compiled pipeline to insert hidden query semantics. For search boxes, from 3.9.0 use the literal text operators (`ILIKE`, `STARTS_WITH`, `ISTARTS_WITH`, `ENDS_WITH`, `IENDS_WITH`, `IEQ`) instead of native regex reads or custom queries; both backends fold case alike, except on `İ` and letters newer than one side's Unicode tables; on PostgreSQL they need a `UTF8` database with ICU, and the expression index that the search needs must be built with `caseFoldExpression('"column"')` from `@simtlix/simfinity-postgres` (see `docs/guide/queries.md`). For records whose own field is missing or empty, from 3.10.0 use `IS_EMPTY`/`IS_NOT_EMPTY` with no value, on scalars, lists and whole embedded objects or lists (a term or group condition without `path`), instead of `EQ null`, which treats `""` as a value and on a list also matches `[null]` and never `[]`; from 3.11.0 they also test references, collections and fields through references, such as "records without a visible professional" (`professional: { terms: [{ operator: IS_EMPTY }] }`), on adapters that declare `queryFeatures.referenceEmptiness`, as both bundled adapters do: a client's condition reads a record that the target's `find` scope hides as a missing one, and conditions that middleware and scopes add read stored data; on 3.10.0, and with other adapters, they fail with `UNSUPPORTED_QUERY`, so keep `EQ null` there and in `find` scopes of types that clients reach through references; emptiness inside an embedded list remains invalid, and collection shorthand excludes emptiness on a leaf (`INVALID_FILTER_PATH`); on a quantifier-capable version use an explicit group for the collection element instead. Prefixed emptiness through collections is no longer universally permanent: frame-local references use scoped joins, while aggregate J paths, embedded-list prefixes and undeclared adapters keep their restrictions. In middleware and scopes, append restrictions and copy the client's filter objects instead of rebuilding them, or the request fails with `DETACHED_CLIENT_FILTER` (500).

For the collection-frame release, first verify the installed version and `queryFeatures.quantifiers` (requires `referenceEmptiness`). Dotted collection paths, relation terms and explicit `ANY`/`ALL`/`NONE` groups use correlated frames; field-filter `quantifier` terms are element-relative and every supplied term needs a path. One group shares one visible child per prefix, while separate groups may use different children. Empty frames satisfy `ALL`/`NONE`, not `ANY`; `NE`/`NIN`/`EQ null` shorthand needs a child, so use collection `IS_EMPTY`/`NONE` for absence. `get_by_id` scopes are trusted and use stored children. List sorts through collections always reject. In aggregates, prefixes used by group/fact paths (J) keep joined-row cardinality; filter-only frames do not multiply facts and a remainder beyond J tests its joined anchor. Explicit groups always remain frames. Respect `maxReferenceFrames` (10 compiled client units/call; a named view's `where` has a separate budget of the same size) and `maxFrameNesting` (3/client or trusted chain), copy marked client objects and never wrap them in trusted quantified groups. Undeclared adapters retain earlier joins and request-time capability errors; do not assume these features exist in the 3.8.0 Barber registry apps.

Verify cross-tenant exclusions, adversarial client filters, aggregate cardinality, rounding, ties/page boundaries and revocation/staleness where relevant. Compare returned totals to authoritative stored/domain values. Deliver the metric definition, query/canonical calculation and evidence; distinguish latency, command count and query-plan cost when making performance claims.
